# Generated Output

S³ aims to not be a "black box" where developers can't inspect the code running their app. All output generated by the `.s3` compiler should be human-readable and standard JavaScript/TypeScript code.

## Vercel Target (`--target vercel`)
S³ either emits:
- `.vercel/output/config.json` and `/functions/` following the Vercel Build Output API.
- Or, custom runtime handlers and `.vercel/output/static` HTML depending on the configuration.

Files remain debuggable so AI tools (like v0) and humans can inspect them.

## Node Target (`--target node`)
S³ emits standard Node.js routing and request-handling code.
`page` -> A standard JSX/React-equivalent rendering logic or pre-compiled string.
`route` -> Express/Fastify-like endpoint mapping HTTP verbs and request bodies to `flows`.
`flow` -> A callable server action translating `.s3` checks and limits into standard functional middleware logic.
`entity` -> Compiled Zod/TypeORM/Prisma schema mappings.
